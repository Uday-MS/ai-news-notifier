AI Stage 8
Notification Decision
Not every event deserves a notification.
The AI asks:
● Is it important?
● Does it match the user?
● Is the deadline close?
● Has the user seen similar content?
Only then does it notify.
This reduces notification fatigue.
AI Stage 9
Learning (Future)
This is where the platform becomes smarter over time.
The system observes:
● Which events users open.
● Which opportunities they save.
● Which notifications they ignore.
● Which organizations they follow.
It uses that behavior to improve future recommendations.
For the MVP, we can keep this simple, but the architecture should allow us to add it later.
Model Strategy
Instead of tying ourselves to one AI provider, I recommend an AI Adapter Layer.
AI Engine
↓
OpenAI Adapter
Anthropic Adapter
Open-source Adapter
Future Models
The rest of the application calls the AI Engine, not a specific provider.
That way, if we switch models later, we don't rewrite the application.
Prompt Management
Another recommendation:
Never hardcode prompts inside Python files.
Instead:
prompts/
summary.md
classification.md
tags.md
importance.md
recommendation.md
This allows us to improve prompts without changing code.
AI Safety
The AI should never:
● Modify original content.
● Invent facts.
● Remove source attribution.
Every summary must link back to the original source.
Trust is one of the platform's biggest assets.
